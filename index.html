04 / Flagship project · Master’s thesis

  1. Read

AutoDeploy

My master’s thesis. You give it one model and one config file. It plans, runs and checks the deployment on CPU, GPU and FPGA, and remembers every attempt for next time.

  • ~63×faster, start to finish
  • ~40×less expert time
  • ~10×more setups tried

↓ Scroll to follow one model through the six steps.

1 / 6

Read the model

Like a mechanic’s inspection: 13 automatic checks look at the model and the machine, then write one short report, the StateContract, that the planner can trust.

  • 13automatic checks
  • 10.58 sonce per model

2 / 6

Remember what worked

Every past attempt, good or bad, lives in a knowledge graph. A new model starts from similar past runs instead of from zero. Node names come from my real Neo4j database.

  • 0.58 → 0.76right picks in the top 5
  • 14% → 8%bad suggestions

3 / 6

Plan the best options

Four planners suggest complete deployment recipes. Each dot is one recipe: further left is faster, higher is more accurate. Recipes that break a hard rule are dropped before they cost anything.

  • 40 minvs 95 min, random search
  • 0.45 msvs 0.68 ms, random search

4 / 6

Run, check, repair

Each step runs in a sandbox and is checked before the next one starts. If a step fails, AutoDeploy repairs it, swaps the tool or rolls back. Each square is one real step from the evaluation.

  • ~320steps run
  • 88%finished, some after a repair

5 / 6

One workflow, many chips

The same config deploys to a CPU, a GPU and an FPGA with no hand-written code for each. On the V100 it picked tuned FP16 over INT8, because Volta’s Tensor Cores only speed up FP16.

  • 0.45 msGPU, measured
  • 72 µsFPGA, HLS estimate

6 / 6

Learn from every run

Every result flows back into the graph, so the next deployment starts smarter: fewer tries and fewer dead ends.

  • 8 → 2tries before the first working setup
  • 35% → 8%setups that fail

Warm-start values are partially estimated in the thesis.

AutoDeploy lab · Real thesis numbers

Try AutoDeploy yourself.

The problem it solves: one trained model, one chip, and many ways to run it. Some are fast, some keep more accuracy. Pick a chip and how much accuracy you can give up, then start the race. Astroparticle physics · CHEP 2024

          
Finding gamma-ray bursts in noise

          
11.5σ on GRB 221009A

          
LHAASO-WCDA has 3,120 PMTs in three water pools (1,320 + 900 + 900), each firing at about 35 kHz. A trigger throws away faint showers, so I used Bayesian optimization to tune a triggerless detection algorithm, revealing gamma rays below 100 GeV that trigger methods could not see. Switch between the two modes above.
